# CapCut cinematic cards

Work through local files and terminal only. No computer use, UI automation, external API key or MCP server. Python 3.10+ runs the helper; FFmpeg/ffprobe provide source evidence. Resolve `scripts/cards.py` relative to this skill. Read [the editing guide](references/editing.md) before choosing cards, and [the command/plan reference](references/tool.md) before staging.

## Image-first author checkpoint

Opening media with the host's image-view tool is necessary work, not computer use. Before writing a card plan, open the supplied visual reference, relevant portraits, actual entrance/context frames and all proposed hold frames. Listing files, reading manifests and generating sheets are not viewing them. The author cannot defer their own visual judgment to a future parent/reviewer. Keep actual image-view paths/receipts separate from editorial conclusions; do not claim an image was reviewed without a corresponding image-view call.

Image delivery alone does not establish correct recognition. Use small batches with source/time labels, and write what is actually visible in each frame immediately after viewing it, before the next batch or context compaction. Count cells/frames, not image files: several dense sheets can contain a hundred observations. Open a dense sheet separately and record its cells before the next sheet. Separate observed people/props/settings from screenplay assumptions. Do not propagate the expected character name across every frame. Reopen decisive first/last/cut frames when reconciling a plan with those observations. A later trace must inspect successful image payloads as well as tool inputs, including array/loop calls; absence from a compacted memory or literal-path search is not evidence an image was never opened.

For decisive full-size frames, use one image per tool call. Immediately record its exact filename, timeline time, `inside_hold`, visible subjects and layout finding before opening the next image. `inside_hold: false` means context outside the card interval; establish an actual cut or identity change from the source/time evidence and visible frames, rather than from the next card in a list.

First appearance means visible in the edited film. Map decisive source timestamps into an included **video** interval from `inspect.sources`, accounting for trim/speed. For its flattened constant-speed interval, `source_time = source_start + (timeline_time - start) * speed`; the retained source end is `source_start + (end - start) * speed`, not division by speed. Prefer the helper's recorded probe mapping over mental arithmetic. A recognizable face in discarded source footage or a longer detached audio interval cannot establish an earlier visual appearance.

To conclude a person is absent from earlier footage, open the whole retained VIDEO interval being excluded, including every generated frame and both sides of internal cuts. A representative sheet that selects a few early frames and omits the remaining shot cannot establish absence. Build small ordered sheets with all those frames; document any still-unseen intervals instead of calling the next clear portrait the first appearance.

Capture the complete visual target: both name and detail lines, including font, size, color, spacing, shadow and stored scale fields. For an approved paired native appearance, use the supported `card_appearance` input instead of approximating it with theme defaults; preserve independently stored clip and uniform scales. A title-only material is not a complete film style; a theme's default role color is not evidence of the supplied reference. Use actual native examples to sanity-check long-line footprints, then shorten or deliberately wrap before shrinking. A safe anchor inside a declared rectangle does not establish that the glyphs fit that rectangle.

For a blind trial, split the fresh author's work into two tasks. First request **visual discovery and evidence only, no plan or stage**: inspect earlier neighboring sources as well as the named scene, record first recognizable appearances separately from later usable holds, and open the evidence. The orchestrator checks actual image-view coverage before continuing that author to plan/stage. If coverage is missing, complete discovery first; do not run another identical one-shot drafting task. The independent staged-product reviewer remains a separate later gate. This checkpoint establishes that images were seen, not that their interpretation or native layout is correct.

## Workflow

1. **Capture the job.** Keep a short local brief with the full current request and supplied visual targets, including earlier requirements still in force. Record requested ending/native fade in plan `requirements`; these are checked, not inferred from “cinematic.” A fresh agent receives this brief and raw assets, without a prior plan's answers. Run `projects`, then `inspect PROJECT`; resolve the indexed main timeline, not the project index ID. Accept readable schema360000 only.
2. **Map the film before placing titles.** Read screenplay, current captions, portraits and available scene/source/cast lists. Identify each source version first: an original screenplay and an expanded production shot list may use different scene numbers. Join by verified dialogue/content and production filename, never the same numeric index across versions. Record that crosswalk, then join to `inspect.sources` and current timeline time. Actual frames outrank an intended shot/cast list. For every principal, locate the earliest recognizable appearance, distinguish disclosure from a background glimpse, and verify the matching person visually. Put the source/scene, actual time and evidence in `character_review` and the card's `first_appearance`. A later clear portrait does not establish the first appearance. Account for every principal with a linked introduction or specific omission; use `introduce_characters: true` and each card's `characters` IDs. Default to name plus a short established role in `detail`; document unknown/spoiler-sensitive role omissions.
3. **Choose reading events.** Add time/location only for a change the audience actually needs explained; record why each is needed. For each named day or time jump, cite the explicit story cue and match its production content to the retained VIDEO interval, checking the preceding/following beat and captions. Daylight alone does not establish a weekday, and a label that is true in a later scene does not justify showing it earlier. Anchor it to the beginning of the corresponding scene/fade, rather than discovering a later attractive frame. At an opening where place and protagonist are already clear, consider one combined identifier instead of successive location and person cards. A small person identifier can appear during dialogue. Start near the first recognizable view, not after their scene or speech. Fit its complete hold to shots where the same person remains unambiguous. An established pair may share a card; independent labels each follow their own person and first entrance.
4. **Review complete holds.** Use `probe` with four seconds before and five after where available. It samples every0.5s, timeline source boundaries and heuristic cuts inside footage. Open all footage frames covering the hold, including immediately before/after each cut; review audio offsets, current captions, overlays/transforms and scene evidence. New plans use `version: 2`, pin `evidence.manifest` and list the full selected-frame sequence. A character hold crossing a detected cut needs `cut_continuity` identifying the same principals on both sides, or ends before that cut. A single portrait or a static logo cannot prove the hold. Cut detection is a guide; inspect visually for cuts it misses. Keep first/last-frame identity, faces/hair, gestures, props and complete subtitle boxes clear. Keep original transitions and picture timing unchanged.
5. **Design against real evidence.** Choose one film-specific font system with installed glyph coverage. Position labels by the actual person's side and negative space through the whole hold, not by one upper/lower-third preset. Review both lines and all glyph edges. `bounds` are declarations; the helper checks anchors and declared collisions, not native glyph metrics. Use a known native rendered example/template when available. If native dimensions are unknown, report them as unresolved; guessed pixels per native size, character counts and a Pillow mock cannot prove fit. Shorten or deliberately wrap a long location before shrinking it. A concise character label may use2–2.8s to end before a cut; choose duration for reading, normally3.2–3.6s when the shot permits it. For a genuinely shorter shot, version2 can retain a shorter hold of any card kind with a specific `evidence.short_hold_review`; the independent reviewer must still pass reading time. A time/location card must begin in its actual scene, rather than moving into the preceding scene to satisfy a normal duration recommendation. Native in/out durations must leave a visible plateau. Never extend a label onto a different person just to meet a numeric minimum, or silently call a later usable portrait the first appearance. Do not extend black to hold a card.
6. **Use supported native styling.** `fade_seconds` creates opacity keyframes. An explicit fade request needs the reviewed native `native_fade_in` option: an existing entry or in/out pair, optionally imported read-only from another local project. Pin source revision and all effect resources; preserve different user effects. An ending requested in the brief uses `kind: ending` over a safe existing final hold. For an authorized subtitle appearance change, read [subtitle layout](references/subtitle-layout.md) and use `subtitle_template` from a reviewed native example. It retains cue words/timing/recognition, copies the working appearance including enable flags, synchronizes content/base_content and optionally raises/wraps text. Keep subtitles editable. If a particular cue covers a meaningful hand/prop action, use reviewed exact-ID `subtitle_template.cue_positions` rather than moving every subtitle. Check that entire cue, including any tail after a card ends and across the following source cut; preserve wording/timing and use an explicit balanced wrap when needed. Do not replace an unsupported guess with PNGs or another ad-hoc writer.
7. **Stage, then expose the whole product.** `stage` creates backups and proposed editable data without project writes. Run `review STAGE --out FRESH_REVIEW_DIR`: it assembles every probe footage frame inside/adjacent to each actual staged hold and exports neutral staged text/transforms in `bundle.json`. It includes intermediate probe frames even if the author did not select them. Static same-aspect uniform zoom/pan is reconstructed from the actual staged draft before drawing the yellow card rectangle; cyan marks an image overlay's geometric extent. Unsupported geometry is refused rather than silently approving raw framing. Sheet order/times are in the bundle. Open every sheet and decisive full-size `display_frames`, retaining raw frames for source evidence. This is geometry review, not native glyphs, effects or compositing. A manifest listing is not an image-view record. Do not write “reviewed” for frames merely listed.
A visible-text preview is a separate artifact from the neutral geometry sheets. When the user chooses preview, use `preview STAGE --calibration LOCAL.json --out FRESH_DIR` with observed typography for the actual font, native size, spacing and clip scale. Optional Pillow is required for this command. Calibrate against known rendered examples; never invent a universal native-size-to-pixels multiplier. Open the rendered letters through whole holds, including all cuts and first/last fade samples; an anchor or yellow rectangle cannot catch text clipped at a canvas edge. Keep the calibration and private preview outside the public skill. The manifest records reconstruction limits and `native_render_verified: false`; approximate font/shadow/wrapping or opacity playback is not a claim about CapCut's engine. If the user explicitly chooses this preview over an export, respect that choice and deliver the reviewed preview without repeatedly demanding a full-film export. Preserve unresolved native differences as limitations, rather than blocking on an export the user declined.

8. **Independent visual gate.** When subagents are available, send a new reviewer with `fork_turns: none` only the neutral bundle, raw cast portraits/script/production map, supplied visual reference and complete brief. Also send the generated visible-text preview and its calibration/limitations manifest when available; the reviewer must inspect whole-hold glyphs, not only declarations. Do not send author review prose or prior proposed answers. The reviewer must open all pages and record per-frame visible subject IDs, which person the label actually points at, layout and observations; review first entrances, reading time, necessity and subtitle coexistence. Someone merely remaining somewhere in a two-shot is insufficient. Name/role boxes follow the actual person, not a left/right preset or investor behind them. Reviewer writes the verdict contract in the command reference; the author must not fill their own independent verdict. If the reviewer rejects any hold, return to the evidence, correct the cause and regenerate stage/bundle/review. Never reinterpret rejection as passing. Without an independent reviewer, deliver an unreviewed stage and state the missing gate; do not bypass by downgrading the plan.
9. **Apply and judge native output.** New plans require `apply STAGE --review VERDICT.json`; failed, incomplete or stale source review is refused. Finish the concrete stage/review before save/close coordination. Apply also refuses a running editor/stale inputs: never kill or bypass the editor. Then run `verify`. These guards do not establish taste, glyph extents, native subtitle wrapping/backgrounds or animation playback. Judge actual native output for every card/whole hold, long subtitle cues, fade and ending before claiming those achieved. Source-only review remains explicitly non-native. For blind trials, a source/native defect returns to its cause before another fresh run; unit tests, author prose or a few mocks do not finish the trial. Give editable output and guarded recovery; the user does not edit JSON.

Ownership is exact-ID-and-hash based. `stage` continues to refuse changed owned titles. For restyling, compare the current draft with the previous staged draft, record findings and the fresh `inspect.ownership` hashes in `ownership_review`, then use `restyle`. It stages changes without rewriting the ownership file first, preserves saved text/timing/layout/keyframes/defaults/effects, and allows reviewed additions. Use `replace_text: true` only for an intentional wording/case change. Missing IDs and stale reviews still stop the edit. Save and **quit the app** before apply; closing a window can leave CapCut running on macOS (Cmd+Q). Never publish private projects, frames, voices, fonts or credentials.

When the user supplies a subtitle appearance reference or cards must coexist with subtitles, read [subtitle references and layout](references/subtitle-layout.md). Follow the supplied visual target and explicit line-count preference; do not substitute a generic cinematic theme. Adding cards does not authorize restyling or retiming existing subtitles.

For overflow or saved layout repairs, follow the editing guide: native size is not px, anchors are not bounds, preserve approved scale fields unless an explicit scale repair is requested, and measure using the selected font. Preserve existing font/style fields omitted from a restyle; do not lock all films to a family or preset.
