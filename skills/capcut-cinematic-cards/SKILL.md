# CapCut cinematic cards

Work through local files and terminal only. No computer use, UI automation, external API key or MCP server. Python 3.10+ runs the helper; FFmpeg/ffprobe provide source evidence. Resolve `scripts/cards.py` relative to this skill. Read [the editing guide](references/editing.md) before choosing cards, and [the command/plan reference](references/tool.md) before staging.

## Workflow

1. Run `projects`, then `inspect PROJECT`. Resolve the indexed main timeline; never guess from the project index ID. Accept only readable schema 360000. Read the supplied screenplay, transcript and character references locally. If missing, search the project context first. Do not invent exact dates, locations, names or identities.
2. Build a short candidate list. Use time/location cards only when a meaningful change would otherwise be unclear. When character introductions are requested, list **every confirmed principal** in `character_review`, set `introduce_characters: true`, and link introduced IDs through each character card's `characters` list. Record a specific reason for each omission. A shared card may introduce an established pair. Revisit a busy first entrance for a quieter beat in the same scene before omitting it; do not silently deliver a partial cast. Character cards require confirmed identity and earlier-scene review. Default to **name + short, established role** in the film's language; put the role in `detail`. For names-only requests, unknown roles or spoilers, record `evidence.role_omission_reason`. Preserve deliberate mystery and avoid minor-character clutter.
3. Use `probe` around each candidate, including at least four seconds before and five after where available; extend review to cover the entire proposed card. Open the extracted images and review all audio stems with their global offsets, captions and script. Optional local ASR is supporting evidence, never proof of silence. Sources are **uncomposited**, so also inspect transforms, overlays, captions, fades and layers. Unresolved visual/audio mapping means omit or defer that candidate.
4. Protect subtitle readability, faces, gestures, entrances, reactions and reveals. A small character identifier may appear during dialogue; do not delay it solely to wait for speech to end. Place it near the correct person and clear of the complete subtitle text/background bounds. A short black fade does **not** justify extending black over the scene. Anchor meaningful scene changes to the existing fade and bridge into a clear lower-third when safe; do not extend black. Keep original transitions unchanged and record why a later hold is needed. Review the whole hold, not just the cut. Choose one film-specific typographic system; confirm the installed font supports the text language. See the editing guide for character timing and style choices.
5. Write the complete plan yourself, outside the project. Include actual evidence paths/findings and protected ranges. Default to 3.2–3.6 seconds, readable size, restrained opacity fades. `fade_seconds` controls editable opacity ramps; it does not add an animation-tab effect. If the user requests a native fade-in, reuse only a reviewed existing local entry animation through `native_fade_in`, with its source text segment and pinned resource files. Preserve different user effects rather than replacing them. For a requested ending, use `kind: ending` over a safe existing final hold; do not insert time or a fullscreen matte. Generate separate editable text tracks only; do not alter compounds, source media, audio or original transitions.
6. `stage` creates backups and a reviewable draft without writing the project. Complete this before any save/close coordination. `apply` refuses a running editor and stale inputs. Never kill the editor, bypass the check or touch unsaved changes. If busy, report the concrete staged result and blocker. Otherwise apply the authorized edit and run `verify`.
7. Report card text, placement, style, skipped ambiguities and backup location concisely. Distinguish file preservation from CapCut playback: never claim native rendering was verified without actual playback/render evidence. Do not ask the user to edit JSON. Use guarded `restore` for rollback; never overwrite later user edits.

Ownership is exact-ID-and-hash based. `stage` continues to refuse changed owned titles. For restyling, compare the current draft with the previous staged draft, record findings and the fresh `inspect.ownership` hashes in `ownership_review`, then use `restyle`. It stages changes without rewriting the ownership file first, preserves saved text/timing/layout/keyframes/defaults/effects, and allows reviewed additions. Use `replace_text: true` only for an intentional wording/case change. Missing IDs and stale reviews still stop the edit. Save and **quit the app** before apply; closing a window can leave CapCut running on macOS (Cmd+Q). Never publish private projects, frames, voices, fonts or credentials.

When the user supplies a subtitle appearance reference or cards must coexist with subtitles, read [subtitle references and layout](references/subtitle-layout.md). Follow the supplied visual target and explicit line-count preference; do not substitute a generic cinematic theme. Adding cards does not authorize restyling or retiming existing subtitles.
